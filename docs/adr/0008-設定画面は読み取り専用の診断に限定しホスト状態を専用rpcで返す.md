# 設定画面は読み取り専用の診断に限定しホスト状態を専用RPCで返す

## Context and Problem Statement

Paseo 0.8.0 のプラグイン機構は `client.addSettingsScreen` で Settings にプラグイン所有の画面を追加できる。一方、設定値の永続化は `defineSettings` と `server.registerSettings`、クライアントの `useSettings` によるホスト単位の文書で、daemon 側サブプロセスから保存値を読む API は無い。このプラグインの実効設定は daemon の環境変数 `PASEO_ZCODE_INSTALL` と ZCode アプリ側の認証・モデル設定にあり、いずれもプラグインの設定文書からは制御できない。利用者が検出状況や互換性を確認する手段は `paseo plugin logs` と README の表に限られている。

## Decision Drivers

- プラグインの動作は daemon 環境と ZCode 側の状態で決まり、Paseo のホスト設定文書を保存しても provider 側から読めない。
- 読めない設定値を画面で保存できるようにすると、二重管理と「変更したのに反映されない」誤解を生む。
- 障害報告に必要な検出・互換性・スモーク結果は既存の診断コードが持っている。ADR 7 の秘匿方針をそのまま適用できる。
- UI はデスクトップ・モバイル・各テーマで動作する必要がある。

## Considered Options

- 読み取り専用の診断画面をクライアント限定 Settings API と専用 RPC で実装する。
- 設定画面を追加しない。
- 独自ファイルと RPC でサーバー側からも読める設定を実装し、インストール先などを画面から変更可能にする。

## Decision Outcome

Chosen option: "読み取り専用の診断画面をクライアント限定 Settings API と専用 RPC で実装する", because 現行 API で provider の動作に影響する設定を安全に提供できず、利用者に実際の価値があるのは現状の診断情報の可視化だからである。

`client.addSettingsScreen` で Settings → Plugins → zcode-provider → Diagnostics を追加する。共有の 1 つの RPC 契約を server ハンドラーが処理し、既存の `discoverRuntime` と `runRuntimeSmoke` を要求時に実行する。返す値は検出パス、OS/CPU、ZCode 本体と同梱 CLI のバージョン、互換性判定、検証済み artifact との一致、インストール先の書き込み可否、保存マッピング先、任意のスモーク結果に限る。失敗時は `AdapterError` のコード、公開メッセージ、`formatDiagnostic` の sanitize 済み JSON のみを返す。設定値の保存とマイグレーションは行わない。

インストール先の上書きは引き続き daemon 環境変数で行い、画面からは変更できないことを画面と README に明記する。Paseo がサーバー側の設定読取 API を公開した場合は、3 番目の選択肢を再検討する。

### Consequences

- Good, because ログと README にしか無かった検出・互換性・スモーク情報を、desktop・モバイル・各テーマの Settings から確認できる。
- Good, because 設定値の二重管理、誤った変更、保存形式のマイグレーションを持ち込まない。
- Good, because 失敗時も sanitize 済みの情報だけを返し、生の native 出力・標準エラー・認証情報・会話を含めない。
- Bad, because 実効設定の変更手段は依然として daemon 環境変数の手動設定であり、画面からは変更できない。
- Bad, because クライアントランタイム（react / react-native）への開発依存と、サーバーとクライアントを分けた型検査設定が必要になる。
- Bad, because 標準の Provider 診断欄（未実装項目）を置き換えるものではなく、同等の情報も提供しない。

### Confirmation

`server/status.test.ts` で検出成功、環境変数由来の表示、非対応 ZCode、スモーク失敗、想定外エラーの各分岐と、生のエラーメッセージが RPC 応答と診断に含まれないことを検証する。`scripts/check-upstream.mjs` は実コンパイラで client と server の両エントリをコンパイルし、server の provider 登録と client の `addSettingsScreen` 登録を実行して確認する。隔離した daemon の同梱 Web UI から実 ZCode 3.11.2 の値を表示し、host check の実行とコンパクト幅の表示を確認する。詳細は[検証記録](../verification.md)に残す。

## More Information

関連する決定は ADR 2（公開 API のみでの統合）と ADR 7（診断の秘匿とバージョン方針）。Paseo の [settings screens](https://paseo.sh/docs/plugins/v0.8/reference.md#settings-screens) と [runtime modules](https://paseo.sh/docs/plugins/v0.8/reference.md#runtime-modules) を参照する。daemon 側設定の読み出し API が公開された場合、または標準診断欄への接続経路が用意された場合にこの決定を見直す。
