# ZCode 4.0のセッション中のプラグインの一覧にもADR 19の抑止を当てる

## Context and Problem Statement

ADR 19 は、管理下ランタイムのビルドの前に、プラグインの探索（`NodePluginAdapter.discoverPluginsSync`）で `PASEO_ZCODE_SUPPRESSED_PLUGINS` の公式プラグインを外すパッチを当てると決めた。Computer Use と Browser Use は、このプロバイダの単独の Server では動かないので、モデルから隠す。

ZCode 4.0.0（`a4b4445141eb7d3b3e99eada9292775383bfc44e`、Issue #115）は、開いているセッションの skill の一覧と MCP の設定を、設定とプラグインの変化に追従する別の仕組みから読むようになった（`apps/zcode-cli/packages/adapters/src/plugins/live-inventory.ts` の `readEnabledPlugins`、`skills/catalog.ts`、`mcp/config-loader.ts`）。ここは公式プラグインを、探索の結果ではなく、Desktop が公式プラグインを入れる時に書く bundled のマーケットプレイスのパーティション（`marketplaces/zcode-plugins-official/bundled-marketplace.json`）から読み、利用者の設定の `suppressedBuiltins` だけで外す。

既存のパッチは 4.0.0 にもそのまま当たった（1 行ずれる）が、この経路には効かない。`test:stdio-runtime` の ADR 19 の準備に、Desktop と同じパーティションを加えると、元のパッチで作った 4.0.0 のランタイムは `computer-use:computer-use skill visibility` で失敗した。公開済みの 3.18.2-paseo.1 は、同じ準備で全項目を通る。`readEnabledPlugins` には探索の要求が無く、要求の `env` を受け取らない。4.0 でも、プロセスごとに公式プラグインを外す公式の手段は無い。

## Decision Drivers

- ADR 19 の条件を保つ：隠すことだけを変え、モデルへの要求、認証、保存形式、プロトコル、通信先を変えない。Desktop と共有する設定を書き換えない。
- パッチは小さく保ち、上流が該当箇所を変えたら当たらずに失敗するようにする。
- Desktop のデータを共有する利用者でも、Computer Use と Browser Use の skill がモデルに出ないこと。

## Considered Options

- 同じパッチの 2 か所目として、`readEnabledPlugins` の `suppressedBuiltins` の判定に、プロセスの環境変数 `PASEO_ZCODE_SUPPRESSED_PLUGINS` を加える。
- skill と MCP の読み込みの引数に、環境変数を探索の要求と同じように渡す経路を加える。
- 利用者の設定の `suppressedBuiltins` に書き込む。

## Decision Outcome

Chosen option: "同じパッチの 2 か所目として、`readEnabledPlugins` の判定にプロセスの環境変数を加える", because 既存の判定の隣に同じ条件を足すだけで済み、ADR 19 の条件を満たすからである。

- `patches/zcode/0001-hide-suppressed-official-plugins.patch` に、`readEnabledPlugins` の hunk を加える。冒頭の対象の説明は、`suppressedBuiltins` を公式プラグインに当てる 2 か所を挙げる。
- この関数には探索の要求が無いので、Agent のプロセスの環境変数を読む。プロバイダは Server の起動時にこの変数を渡し、Server は Agent に環境を引き継ぐ。
- `test:stdio-runtime` の ADR 19 の準備に、bundled のパーティションを加える。パッチを当てたランタイムでは Computer Use と Browser Use の skill が隠れ、対照のプラグインは見えることを確かめる。
- 外す条件は ADR 19 のまま（ZCode がプロセスごとに公式プラグインを隠す公式の手段を持つこと）。

### Consequences

- Good, because ZCode 4.0 の管理下ランタイムでも、Desktop のデータを共有したまま Computer Use と Browser Use の skill がモデルに出ない。
- Good, because パッチは 1 つのままで、追加は 1 か所の条件だけである。
- Bad, because 2 か所目は要求の `env` ではなくプロセスの環境変数を読む。同じ Agent のプロセスで別の値を使い分けることはできない（このプロバイダは Server ごとに同じ値を渡すので、困らない）。
- Neutral, because `PASEO_ZCODE_RUNTIME` で指定したパッチの無いランタイムでは、これまでどおり `ZCODE_CUA_PRODUCT_HELPER=0` とターンごとの `toolDisallowlist` だけが効く。

### Confirmation

- `npm run check:zcode-patches` で、パッチが `a4b4445` にそのまま当たることを確かめる。
- パッチを当てた 4.0.0 のランタイムで、パーティションを加えた `test:stdio-runtime` が全項目を通ること、元のパッチでは `computer-use:computer-use skill visibility` で失敗することを確かめ、[verification.md](../verification.md) に記録する。
- リリースのワークフローが、5 つのプラットフォームで同じ試験を通す。

## Pros and Cons of the Options

### `readEnabledPlugins` の判定にプロセスの環境変数を加える

- Good, because 変更が小さく、既存の判定と同じ形である。
- Bad, because 要求ごとの `env` ではなくプロセスの環境変数に頼る。

### 読み込みの引数に環境変数を渡す経路を加える

- Good, because 探索と同じく要求の `env` を使える。
- Bad, because skill と MCP の読み込みの呼び出し元を何か所も変える大きなパッチになり、上流の変更で当たらなくなりやすい。

### 利用者の設定の `suppressedBuiltins` に書き込む

- Good, because パッチが要らない。
- Bad, because Desktop と共有する設定なので、Desktop でも Computer Use と Browser Use が無効になる。ADR 19 が退けた選択肢である。

## More Information

- ADR 19 の「パッチの内容」に、2 か所目の対象と読み方を加える。パッチの条件、形式、配布物の表示、版の付け方は変えない。
